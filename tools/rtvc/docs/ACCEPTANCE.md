# 完了条件（オラクル）

> 「何をもって合格とするか」を、**AI 以外が判定できる形**で先に固定したもの。
> ここを曖昧にしたまま自走させると、誤解した仕様を検証する条件が作られて空回りする。

作業の種類ごとに、判定できる（モード A）／判定できない（モード B）を分けてある。

---

## A-1. コードが壊れていないこと（判定可能・自動）

```bash
cd tools/rtvc
python -m pytest tests/ -q
```

| # | 条件 | 判定方法 |
|---|---|---|
| 1 | テストが全件通る | 終了コード 0 |
| 2 | 音声デバイス・GPU 無しで通る | CI（GitHub Actions）で通っている＝証明済み |
| 3 | 窓とクロスフェードの算数が合っている | `test_passthrough_output_matches_the_exact_oracle` |
| 4 | アルゴリズム遅延に EXTRA が混入していない | `test_algorithmic_latency_is_block_plus_crossfade_only` |
| 5 | リングバッファが溢れたとき古い方を捨てる | `test_ring_buffer_drops_oldest_on_overflow` |
| 6 | リサンプラが申告どおりの遅延しか持たない | `test_stream_resampler_reports_its_true_latency` |

**#3 が中心。** passthrough なら出力は
「入力を X サンプル遅らせ、ブロック境界の X サンプルに等パワー窓の和を掛けたもの」に
**厳密に一致する**はず。窓の組み立て・末尾の切り出し・のりしろの持ち回りの
どれか一つでも間違えるとこの等式が崩れる。聴感ではなく算数で判定している。

## A-2. 実機のベースラインが再現すること（判定可能・手動）

```powershell
python realtime.py --engine passthrough --in-device 23 --out-device 22 `
  --sr 48000 --io-block 128 --block-ms 32 --crossfade-ms 8
```

| # | 条件 | 合格ライン |
|---|---|---|
| 1 | `TOTAL` | 94.67ms ± 10ms |
| 2 | `under` / `over` / `drop` | すべて 0 |
| 3 | 内訳が既知の値と整合 | in-dev 22 / block 32 / xfade 8 / out-buf 8 / out-dev 24.67 前後 |

**1 つでも外れたら、次の計測に進まない。** 土台が動いていないのに
その上の測定値を積んでも意味がない。

## A-3. 「25ms のモデルに耐えるか」（判定可能・手動）

```powershell
python realtime.py --engine fixed --fixed-cost-ms 25 --in-device 23 --out-device 22 `
  --sr 48000 --io-block 128 --block-ms 32 --crossfade-ms 8
```

| 結果 | 意味 |
|---|---|
| `under` / `drop` = 0 | **合格。** RTF 0.78 まで耐える構成だと確定 |
| `under` > 0 | `--block-ms` を上げる（48 など）か、もっと軽いモデルが必要 |

---

## A-4. WASAPI 排他モード（判定可能・手動）

```powershell
python realtime.py --engine passthrough --in-device 23 --out-device 22 `
  --sr 48000 --io-block 128 --block-ms 32 --crossfade-ms 8 --exclusive
```

| 結果 | 次の一手 |
|---|---|
| 起動して in-dev / out-dev が下がる | **合格。** 各 5〜10ms まで下がる見込み |
| 起動するが値が変わらない | ドライバが排他を無視している。有線マイクへ |
| 起動せず落ちる | 入力だけ / 出力だけ、と片側ずつ試して原因側を特定 |

## A-5. RVC を載せたあと（判定可能・手動）

| # | 条件 | 合格ライン |
|---|---|---|
| 1 | `infer` | < 32ms（RTF < 1）。実運用は RTF 0.6 以下 |
| 2 | `TOTAL` | 口 → 仮想ケーブルで 100ms 以下 |
| 3 | `under` / `over` / `drop` | すべて 0 |

Discord 自体が受信側で 40〜100ms 持つが、**削れないので目標に含めない。**

## B. 判定できないもの（回数を固定する）

**「声が似ているか」「自然に聞こえるか」は数値で判定できない。**
ここに「合格するまで止めるな」を適用すると無限ループになる。

| 対象 | 進め方 |
|---|---|
| 声質の似せ具合 | 学習・調整は**1 周だけ**やって聴く。直したら再評価はせず、次の変更に進む |
| 音の自然さ | 同上。ただし下の代理指標に落とせるものは落とす |

判定できる代理指標に落とせるものは落とす：

- 「途切れる」→ `under` / `drop` が 0 か（**数えられる**）
- 「ブツブツ鳴る」→ ブロック境界で不連続が出ていないか（**測れる**）
- 「遅い」→ `TOTAL` が 100ms 以下か（**測れる**）
- 「こもる」→ `--extra-ms` を 500 → 1000 にして変わるか（**A/B できる**）

**残る「声が似ているか」だけが本当の主観判断。** ここは人間が聴いて決める。

## 権限の線引き

自律化するのは**工程**であって**権限**ではない。

| AI に任せる | 人間が承認する |
|---|---|
| 調べる・作る・直す・検証する | 消す・送る・払う・公開する・本番を変える |

このリポジトリでの具体的な線引き：

- ローカルファイルの削除 → **承認が要る**（`inventory-local.ps1` は読み取り専用）
- 音声モデルの学習素材の追加 → **承認が要る**（→ 声の権利）
- コードの修正・テストの追加・ドキュメント更新 → 任せてよい

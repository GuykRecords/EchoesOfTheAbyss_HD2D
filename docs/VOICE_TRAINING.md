`--engine rvc` を動かすために残っている唯一の作業。**これが終われば実測に進める。**

> **前提の確認。** ここに書いてあるうち、私（Claude）が実際に動かして確かめたのは
> ステップ 2 の判定ツールだけ。RVC の訓練 UI はこの環境では動かせないので、
> **ステップ 4 の画面の文言はバージョンによって違う**可能性がある。
> 迷ったら画面をそのまま見せてほしい。一緒に読む。

## 0. 声の権利（非交渉）

**学習に使ってよいのは自分の声か、明示的に許諾された声素材のみ。**

他人の声の無断クローンは禁止。配布素材でも規約は個別
（例：あみたろの声素材は「変換していることの明記」が条件）。

将来ボイス素材の販売など商用で使うなら、**素材ごとに商用可否を確認してから**使うこと。
「無料配布だから自由」ではない。

### 使える素材の例：つくよみちゃんコーパス

音声合成・音声変換での利用を想定して公開されている。**規約が用途ごとに 6 段階に分かれている**
ので、自分がどこにいるかを確認してから使う。

配布ページ: https://tyc.rei-yumesaki.net/material/corpus/

| このプロジェクトでの段階 | 規約の項 | 条件 |
|---|---|---|
| パイプライン確認（外に出さない） | **①** | **制限なし。クレジットも不要** |
| Discord / OBS で声を出す | **②** | クレジット必須。RVC での利用は明示的にここ |
| モデルを配布・公開する | ③ | クレジット必須。事前にメールで相談が推奨 |
| **ボイス素材として配布・販売** | ⑤ | **原則禁止**（個別相談は可） |

① の原文:

> 本品や、本品の声質を用いて合成された音声を外部に公開しない場合は、
> 何の制限もありません。ご自由にご利用ください。

② で求められるクレジットの文面（原文）:

> 音声合成（「声質の学習」「RVCによる声質変換」など、より具体的に説明しても可）には、
> フリー素材キャラクター「つくよみちゃん」が無料公開している音声データを使用しています。
> ■つくよみちゃんコーパス（CV.夢前黎）
> https://tyc.rei-yumesaki.net/material/corpus/

**副業でボイス素材を売る構想には使えない。** ②・⑤ が「他者に対して二次利用（素材としての
利用）を許可する形での公開」を禁じている。**完成作品としての販売は可**、素材としての販売は不可。
その用途は自分の声で作ること。

用途を問わず禁止されているもの: 人を批判・攻撃する言動、特定の政治的立場・宗教・思想への
賛同/反対の呼びかけ、刺激の強い表現のゾーニングなし公開。

> **公式 RVC モデルが配布されている。** https://tyc.rei-yumesaki.net/work/software/rvc/
> パイプラインの確認だけが目的なら、**訓練そのものを飛ばせる**。
> `.pth` を `assets/weights` に置けば `--engine rvc` がすぐ動く。

## 2. ステップ 1：録音

### 機材と設定

| 項目 | 推奨 | 理由 |
|---|---|---|
| マイク | **有線** | ワイヤレスは圧縮で高域が落ちる。学習素材には向かない |
| サンプルレート | **48000 Hz** | モデルも 48k にするので変換が要らない（→ ステップ 4） |
| ビット深度 | 16bit 以上 | |
| チャンネル | **モノラル** | ステレオだと後で変換が要る |
| 形式 | WAV | mp3 など非可逆は避ける |

> **INZONE Buds（ワイヤレス）は録音には使わない。** 変換して喋る本番では使えるが、
> **学習素材はマイクの質がそのままモデルの質になる**。

### 量

| | |
|---|---|
| 最低 | **10 分** |
| 十分 | **20〜30 分** |
| それ以上 | **効果は頭打ち。** 時間の割に良くならない |

### 何を読むか

**3 つの軸を全部埋めること。** どれか欠けると、その領域だけ変換が破綻する。

1. **音のバリエーション** — 日本語の音を一通り含む文章を読む
   - 「ITA コーパス」「ROHAN4600」などの朗読用テキストが公開されている
   - 無ければ、新聞記事やニュース原稿を 10 分ぶん音読するだけでも成立する
2. **実際の使い方に近い喋り** — Discord で友人と話す声を出したいなら、**朗読だけでは足りない**
   - 普段のテンションで独り言、雑談の再現、笑い声、相槌
   - 朗読だけで学習すると、朗読調のときだけ綺麗で、雑談すると崩れる
3. **音域と勢いの幅** — 低い声、高い声、小声、大きい声、早口、ゆっくり
   - **本番で出す音が学習に入っていないと、そこだけ変換が壊れる**

### 環境

- 静かな部屋。**エアコンと PC ファンを止められるなら止める**（環境音は判定で弾かれる）
- マイクとの距離を一定に保つ（近づいたり離れたりしない）
- 破裂音（パ行・バ行）はポップガードか、口をマイクから少しずらす
- **ピークは -6 dBFS くらいを狙う。** 大きく録りすぎてクリップさせるより、小さめが安全

### ファイルの分け方

- 1 本 **2〜15 秒**。中央値 5〜10 秒あたりが扱いやすい
- **前後に 0.3 秒ほど無音を残す** — 環境音の判定にこの無音を使う
- 置き場所（例）: `D:\Claude\Project\voice\raw\`

## 2-B. ステップ 1 の代替：既存の音源を使う

新しく録らず、**手元にある音源**（MP3 など）を使ってもよい。ただし条件がある。

### 使える音源の条件

| 条件 | 理由 |
|---|---|
| **権利を持っている** | → §0。自分の声か、明示的に許諾された素材のみ |
| **話者が 1 人だけ** | 複数人が混ざると、その全部が 1 つの声として学習される |
| **BGM・効果音が入っていない** | 分離はできない。音楽ごと声質として学習される |
| 残響が強すぎない | 部屋鳴りも声の一部として学習される |

対談・複数人の配信アーカイブ・BGM 付き動画は**そのままでは使えない**。
自分だけが喋っている区間を切り出せるなら使える。

### MP3 など非可逆圧縮の音源について

**上限は元の音質のまま**。MP3 の時点で削られた高域は戻らない。
48kHz にアップサンプルしても情報は増えない（ツールがそう警告する）。

「使えない」わけではない。**ただ、同じ手間なら WAV で録り直した方が良いものができる。**
既存音源で試して、物足りなければ録音に切り替える、という順番でよい。

### 切り分け

MP3 は 1 本の長いファイルで、そのままでは学習に使えない。
**48kHz / モノラル / 2〜15 秒 / 前後に無音** の WAV に切り分ける。

```powershell
D:\Claude\Project\.venv-rvc\Scripts\Activate.ps1
cd D:\Claude\Project\voice-lab

# まず結果だけ見る（何も書き出さない）
python scripts\prepare_dataset.py D:\voice\source.mp3 --out D:\voice\raw --dry-run

# 良さそうなら実行
python scripts\prepare_dataset.py D:\voice\source.mp3 --out D:\voice\raw
```

**入力ファイルは一切変更しない。** 出力先が空でなければ止まる（`--force` で上書き可）。

やっていること:

1. 読み込み（WAV は scipy、それ以外は soundfile か ffmpeg）
2. モノラル化して 48kHz にリサンプル
3. ピークを −6 dBFS に正規化
4. **無音で区切って 2〜15 秒に切り分ける**（前後に 0.3 秒の無音を残す）
5. 長すぎる区間は、内側の一番静かなところで割る

しきい値は「絶対値」と「その音源の中で一番大きい音から 35dB 下」の**大きい方**。
小さめに録れた音源が丸ごと無音扱いになるのを防ぐため。

出力には**元の長さと保持率**が出る。

```
ena_voice_all.wav  48000Hz  元 18.4 分 → 174 本 / 8.8 分（保持 48%）
```

**保持率が 50% 前後なのは、間の多い収録では正常。** 読み上げの合間、言い直し、
息継ぎが落ちているだけ。50% を大きく下回るときだけ `--silence-dbfs` を下げるか
`--min-silence` を伸ばす。`--dry-run` で何度でも試せる。

> **ファイル名が日本語でも動く。** 「ダ」を 1 文字で持つ書き方（NFC）と
> 「タ + 濁点」で持つ書き方（NFD）は画面上で区別できず、片方で指定すると
> **一覧に見えているのに「見つかりません」**になる。両方を解決するようにしてある。

MP3 / FLAC を読むには `soundfile` が要る。

```powershell
pip install soundfile
```

**録り終わったら必ずこれを通す。** 訓練前の 1 分が、3 時間の無駄を防ぐ。


読み取り専用。ファイルは一切変更しない。

```

長さ  最短 3.1s / 中央 6.8s / 最長 14.2s
レート [48000]
ピーク -12.4 〜 -5.9 dBFS  |  環境音 -68.2 〜 -61.4 dBFS

合格。この素材で学習に進んでよい。
```

### 判定基準（先に固定してある）

| 項目 | 基準 |
|---|---|
| 総時間 | 10 分以上（20 分で十分） |
| 1 本の長さ | 2〜15 秒 |
| サンプルレート | 40000 Hz 以上、かつ**全ファイルで統一** |
| チャンネル | モノラル |
| ピーク | -1 dBFS 以下、クリップ 0 サンプル |
| 環境音 | -50 dBFS 以下 |
| 無音の割合 | 60% 未満 |
| 直流オフセット | ±0.003 以内 |

指摘は**種類ごとにまとめて**出る。100 本が同じ理由で落ちても 100 行にはならない。

> **「無音区間が無く環境音を判定できない」**と出たら、切り詰めすぎ。
> 前後に 0.3 秒の無音を残して切り直す。環境音の推定にそこを使っているため。

`-v` を付けると全ファイルの数値が出る。

### 基準を下げたときは、下げたと記録する

`--min-minutes` で総時間の基準だけは下げられる。**今回はそれを使った。**

```powershell
python scripts\check_dataset.py D:\Claude\Project\voice\ena --min-minutes 8
```

実データ（ena）は **174 本 / 8.8 分**で、既定の 10 分にわずかに届かない。
他の項目（レート 48000 統一・ピーク -14.8〜-6.7 dBFS・環境音 -148.7〜-137.4 dBFS）は
すべて余裕を持って通っている。**足りないのは量だけ**なので 8 分まで下げて進めた。

> 8.8 分は「学習は回る」量であって「十分」ではない。
> 出来上がりの声が場面によって崩れるようなら、**まず素材を足す**。
> エポック数やパラメータをいじるより効く。

## 4.5 `.venv-rvc` から RVC を動かすと、子プロセスが落ちる

**先に読むこと。読まないと 1 時間溶ける。**

`webui.py` の「データ処理」を押すと、Gradio 画面にはこう出るだけ。

```
【データ分割】
状態：失敗
RuntimeError: 子プロセスが終了コード付きで失敗しました: [1]
```

**この文言には原因が入っていない。** 本当のエラーは `webui.py` を動かしている
ターミナルの方に出る。`logs\<実験名>\preprocess.log` は 0 バイトのまま
（音声を読む前に死ぬので、1 行も書けない）。

### 何が起きているか

`webui.py` は子プロセスをこう起動する（`webui.py` 867 行目あたり）。

```python
cmd = '"%s" train/preprocess.py ...' % config.python_cmd
```

`python なんとか.py` という呼び方をすると、Python は**そのスクリプトのあるフォルダ**を
検索先の先頭に置く。つまり子プロセスの基準は `RVC\train\` になる。すると:

| 症状 | 理由 |
|---|---|
| `ModuleNotFoundError: No module named 'infer'` | `infer` は一つ上の `RVC\` にあるので見えない |
| `ImportError: cannot import name 'utils' from partially initialized module 'train'` | `RVC\train\train.py` が `train` フォルダより先に見つかる。`train.py` の中の `from train import utils` が自分自身を指し、循環する |

### 上流が壊れない理由

`go-webui.bat` を読むと分かる。

```
runtime\python.exe -I webui.py --pycmd runtime\python.exe --port 7897
```

- **同梱の `runtime`** — 携帯版 Python には `python3xx._pth` が入っていて、RVC 直下が検索先に入る
- **`-I`（isolated モード）** — その効果のひとつが「**スクリプトのあるフォルダを検索先に加えない**」。これで `train\train.py` が邪魔をしない

`.venv-rvc` にはどちらも無い。**素材の問題でも設定の問題でもなく、起動作法の差**。

`--pycmd` から `-I` を渡すことはできない。値は `'"%s" train/preprocess.py'` と
引用符で囲まれるので、`"python -I"` は「そういう名前のプログラム」を探しに行って失敗する。

### 対処：`.pth` を 1 つ置く

`.venv-rvc` の site-packages にこれを置く。**RVC もこのリポジトリも 1 行も書き換えない。**

```powershell
Set-Content -Path D:\Claude\Project\.venv-rvc\Lib\site-packages\_rvc_root.pth `
  -Encoding ascii -Value @("D:\Claude\Project\RVC", "import train, infer")
```

2 行の意味:

| 行 | 効果 |
|---|---|
| `D:\Claude\Project\RVC` | RVC 直下を検索先に加える（`._pth` の代わり） |
| `import train, infer` | **`RVC\train\` が割り込む前に**、正しい方を読み込ませて `sys.modules` に載せる |

2 行目が肝。Python は一度読んだモジュールを二度は探さない。`.pth` は
インタプリタ起動のごく早い段階（スクリプトのフォルダが検索先に入る**前**）に
実行されるので、ここで先に正解を掴ませれば、あとから `train.py` が現れても無視される。

`train` も `infer` も `__init__.py` を持たない空の入れ物（namespace package）なので、
先読みのコストはゼロに近い。重い処理は走らない。

### 効いたことの確かめ方

**RVC と無関係な場所から**呼ぶこと。カレントディレクトリの偶然で通ってしまうのを防ぐ。

```powershell
cd C:\
D:\Claude\Project\.venv-rvc\Scripts\python.exe -c "from infer.audio import load_audio; print('OK')"
D:\Claude\Project\.venv-rvc\Scripts\python.exe -c "import train; print(train.__path__)"
```

期待する出力:

```
OK
_NamespacePath(['D:\\Claude\\Project\\RVC\\train'])
```

`train.py` ではなく **`train` フォルダ**を指していること。

### 元に戻す

```powershell
Remove-Item D:\Claude\Project\.venv-rvc\Lib\site-packages\_rvc_root.pth
```

これで `.venv-rvc` は完全に元通りになる。

### 実測（この対処のあと）

```
[データ分割] Pending: 174 | プロセス数: 19
[データ分割] 完了
データ抽出完了：合計所要時間=19.047秒
```

174 本すべて成功、失敗 0。**死んでいたときは 1.0 秒**で終わっていた（起動即死）。
所要時間が桁で変わるので、成否はそこでも見分けられる。

## 5. ステップ 4：訓練する

```powershell
D:\Claude\Project\.venv-rvc\Scripts\Activate.ps1
cd D:\Claude\Project\RVC
$env:GRADIO_ANALYTICS_ENABLED="False"
python webui.py
```

> **起動スクリプトは `webui.py`。** 古い RVC の記事にある `infer-web.py` はこのリポジトリには無い。
> `go-webui.bat` を叩いても同じものが立ち上がるが、そちらは自前の venv を見に行くので使わない。
>
> `GRADIO_ANALYTICS_ENABLED="False"` は Gradio の外部通信を止めるためのもの。無くても動く。

ブラウザで開いた画面の「訓練 / Train」タブで作業する。

### 設定（画面の文言はバージョンで違う。意味で読むこと）

| 設定 | 値 | 理由 |
|---|---|---|
| モデル名 | 半角英数字（例 `ena`） | **日本語やスペースを入れない**。パスで落ちる既知問題 |
| バージョン | **v2** | |
| **目標サンプルレート** | **48k** | ← **下の注を必ず読むこと** |
| 音高（f0）の抽出 | **あり** | 無しだとピッチが変換されない |
| f0 抽出方法 | **rmvpe** | 本番の推論と揃える |
| 学習データのパス | `D:\Claude\Project\voice\ena` | `prepare_dataset.py` の出力先。**`raw` ではない** |
| バッチサイズ | **6** | ← 下の注。48k では 8 を勧めない |
| エポック数 | **150** | 下の「止めどき」を参照 |
| メモリにキャッシュ | **はい** | 10 分以下の素材なら速くなる |
| 各保存時点の小モデルを全部 weights に保存 | **はい** | **ここが最重要。** 下の「止めどき」が成立しなくなる |
| 保存頻度 | **10 エポックごと** | 途中の重みを残す。これが効く |
| 最新の小モデルのみ保存 | **オフ** | 途中のエポックを聴き比べたいので全部残す |

> ### バッチサイズは 6 から。8 ではない
>
> 一度このドキュメントに「8 から始める」と書いたが、あれは 40k を前提にした数字だった。
> **48k は 40k より重い。** 12GB で 8 を選ぶと OOM の目が出る。
> 20 分走ってから落ちると全部やり直しなので、**6 で始める**。
> 実測（RTX 4070 12GB / 48k / v2 / バッチ 6）では **1 エポック 11 秒**、OOM なし。

> ### 目標サンプルレートは 48k を選ぶ
>
> 40k を選ぶと、変換後に 40k → 48k のリサンプルが要る。**これは整数比ではない。**
> このプロジェクトでの実測では、
>
> | 比 | 再構成誤差 |
> |---|---|
> | 整数比（48k ↔ 16k / 24k / 48k） | **−56 dB** |
> | 非整数比（48k ↔ 40k / 44.1k） | **−35 dB** |
>
> **20 dB の差**を、選択肢を 1 つ変えるだけで避けられる。
> 40k を選ぶと `RVCTorchEngine` が起動時に警告を出す。

処理の順番は「前処理 → 特徴抽出 → 訓練 → index 作成」。
**index の作成まで忘れずにやること**（`--rvc-index` で使う）。

### 止めどき — ここは数字で決められない

**「声が似ているか」は損失の数字では判定できない。**
損失が下がり続けても、ある時点から**過学習**して「学習データの読み上げ方」に
引っ張られ、雑談で崩れるようになる。

そこで、**回数を決めておく。**

1. 100 / 150 / 200 エポック時点の重みで、**同じ音声**を変換して聴き比べる
2. **一番良かったものを採用してそこで終わり**
3. **「もっと良くなるかも」で延々と回さない** — 判定基準が無い作業に終わりは来ない

数値で判定できるもの（`infer` 時間、`under`、`TOTAL`）はツールが自動で見る。
**残る「声が似ているか」だけが、あなたが耳で決める部分。**

## 5.6 訓練が終わったら：エポックを聴き比べる

`assets/weights` に `ena_e10.pth` 〜 `ena_e150.pth` の 15 個ができている。
**どれを使うかは耳で決める。** 損失の数字では決められない（→ §5「止めどき」）。

### 手順

同じ音声を、違うエポックのモデルで変換して並べる。**入力は必ず同じもの**を使うこと。
前に録った `take3.wav`（`--record-in` で保存した生の入力）がそのまま使える。

```powershell
D:\Claude\Project\.venv-rvc\Scripts\Activate.ps1

$w = "D:\Claude\Project\RVC\assets\weights"
foreach ($e in 50, 100, 150) {

    --offline-input take3.wav `
    --rvc-model "$w\ena_e$e.pth" `
    --offline-out "ena_e$e.wav"
}
```

**`--rvc-model` はファイル名ではなくパスで渡す。** 省略すると
`assets/weights` の**名前順で最初の 1 個**（= `ena_e10.pth`）が選ばれてしまう。

### 聴きどころ

| 見るところ | 悪いとどうなるか |
|---|---|
| **語尾** | 過学習だと語尾が溶ける・甘くなる |
| **早口** | 学習素材に無い喋り方が最初に崩れる |
| **小声 / 大声** | 音量の端で音程が暴れる |
| **似ているか** | エポックが少なすぎると元の声が残る |

**エポックは多いほど良いわけではない。** 8.8 分という少なめの素材では、
150 まで回すと「学習データの喋り方」に引っ張られて、雑談で崩れることがある。
50 や 100 の方が良いことは普通にある。

一番良かった 1 個を決めたら、**そこで終わり**。「もっと良くなるかも」で回し続けない。

## 5.7 まず `--rvc-key` を合わせる。話はそれから

**声が似ていないと感じたら、モデルを疑う前にピッチを疑うこと。**

RVC が変換するのは**声色**であって、**音の高さは入力のまま**（`--rvc-key` で移調するだけ）。
男声の音程のまま女性モデルを鳴らすと、音色は変わっていても**「自分の声」に聞こえる**。
人が話者を判断するのに音程が強く効くため。

### 実測（ena / take3.wav / e100）

| `--rvc-key` | 印象 |
|---|---|
| 0 | **自分の声のまま。** モデルが効いていないように聞こえる |
| 6 | まだ自分っぽい |
| 9 | 良い |
| **12** | **最良。別人で、無理がない** |
| 15 | 別人だが、やや甲高い |

男声 → 女声は **+12 半音（1 オクターブ）** が定石。実測もそのとおりだった。

> ### エポックの聴き比べは、ピッチを合わせてからやること
>
> 最初、k=0 のままエポック 30/60/100/150 を比べて「差が無い」と結論しかけた。**あれは無効。**
> k=0 ではどれを使っても自分の声に聞こえるので、**ピッチという大きな差にエポックの差が埋もれる**。
> 4 本の Hash は全部違っていた（＝モデルは切り替わっていた）のに、耳では区別できなかった。
>
> **比較は一度に一変数。** 先に `--rvc-key` を決め、そのうえでエポックを比べる。

### `--rvc-model` を明示すると、索引の自動検出が効かない

`build_rvc_engine` は `--rvc-model` が無いときだけ `find_first_model()` に索引を探させる。
明示したときは `--rvc-index` も自分で渡すこと。

さらに `find_first_model()` は「.pth の名前が .index の名前に含まれる」ことを当てにしているが、
RVC の実際の名前は噛み合わない。

```
ena_e100_s3600.pth
added_IVF681_Flat_nprobe_1_ena_v2.index
```

`ena_e100_s3600` は後者に含まれないので、**自動検出は当たらない**。当面は明示で回避する。

## 5.8 index が「無効」と言われるのは、たいてい index のせいではない

`--rvc-index-rate` を 0 より上げると、毎ブロックこれが出ることがある。

```
インデックス検索を有効化しました              ← 読み込みは成功している
無効なインデックスです。使用してください: added_xxxx.index, not trained_xxxx.index
```

**メッセージを信じないこと。** ファイル名は関係ない。`infer/rtrvc.py` 249 行あたり:

```python
score, ix = self.index.search(npy, k=8)
if (ix >= 0).all():
    ...混ぜる...
else:
    printt(i18n("索引无效：必須added_xxxx.index..."))
```

例外ではなく `else`。**faiss が 8 件そろえられず `-1` を返した**だけで、RVC はその
1 パターンしか想定していないので、無関係な原因を名指しする。

理由は index の名前が言っている。

```
added_IVF681_Flat_nprobe_1_ena_v2.index
                          ^^^^^^^^
```

IVF は 26,585 本のベクトルを 681 区画に分けて持つ。`nprobe=1` は「1 区画だけ見る」で、
平均 39 本の区画でも、少ない区画に当たれば 8 件に届かない。1 件でも欠ければ
**そのブロックの index 合成は丸ごと捨てられる**。既定のままでは実質的に機能しない。

### 対処：`--rvc-index-nprobe`（既定 16）

`rtvc` 側で faiss の `nprobe` を広げるようにした。**index を作り直す必要はない。**

```powershell
python -m rtvc.realtime --engine rvc --offline --offline-input take3.wav `
  --rvc-model "...\ena_e150_s5400.pth" --rvc-key 12 `
  --rvc-index "...\ena_added_IVF681_Flat_nprobe_1_ena_v2.index" --rvc-index-rate 0.5 `
  --offline-out out.wav
```

起動時の `rvc params` 行に `nprobe=16` が出る。効いていれば
`無効なインデックスです` は消える。**消えないなら別の原因**なので、そこで切り分ける。

`--rvc-index-nprobe 0` で faiss の既定（1）に戻せる。

### 索引ありの実測（e150 / key 12 / take3.wav）

| index_rate | infer ema | RTF |
|---|---|---|
| 0.0（索引なし） | 11.1 ms | 0.085 |
| 0.25 / 0.5 / 0.75（**失敗していた**） | 12.6〜12.8 ms | 0.097〜0.099 |

失敗していても検索自体は走るので、時間は増える。**上の表の下段は「索引の効果」ではなく
「索引を試みて捨てた」コスト**。130 ms のブロックに対して 13 ms なので、
成立させても余裕は十分ある。

## 7. うまくいかないときの順番

### 速度が足りない（`infer` が大きい / `under` が出る）

1. `eng.tail_aware` が `True` か確認（起動ログに出る）。効いていなければ約 3.4 倍損している
2. `--f0-method rmvpe` → `fcpe` に落とす
3. `--rvc-index-rate 0.0`（faiss を切る）
4. `--extra-ms 100` → `80` に減らす（**遅延ではなく計算量が減る**。10 の倍数を維持）
5. `--block-ms 30` → `40` に**増やす**（推論回数が減り RTF が下がる。遅延は増える）

**`--crossfade-ms` を削って速度を稼ごうとしないこと。** X は計算量にほぼ効かず、
削ると継ぎ目が鳴るだけで損しかしない。

### 音は出るが声が似ていない

- 学習素材に**その喋り方が入っていたか**を疑う（朗読だけで学習していないか）
- エポックを変えた重みを聴き比べる（過学習していないか）
- `--rvc-index-rate` を 0.0 → 0.3 に上げてみる（速度と引き換え）

### 音が途切れる・ブツブツ鳴る

- `under` / `drop` が 0 か確認。0 でなければ速度不足（上へ）
- 0 なのに鳴るなら `--extra-ms` を 100 → 200 に増やす（**遅延は増えない**）
